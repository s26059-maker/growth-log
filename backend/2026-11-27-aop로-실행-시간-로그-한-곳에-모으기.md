# AOP로 실행 시간 로그 한 곳에 모으기

> 📅 2026-11-27 · 백엔드 기초 · 70점
> `#Spring` `#AOP` `#프록시`
> 메서드마다 복붙하던 실행 시간 측정 코드를 프록시 원리로 @Aspect 하나에 모으고, @Transactional이 같은 원리로 동작한다는 것까지 연결

## 복붙 코드의 문제

```java
public void pay(Long orderId) {
    long start = System.currentTimeMillis();
    // 결제 처리
    long end = System.currentTimeMillis();
    log.info("pay 실행 시간: {}ms", end - start);
}
// refund()에도 똑같이 복붙...
```

- 메서드가 n개면 같은 코드를 **n군데**에 써야 해
- 시간 재는 방식을 바꾸면 n군데를 다 고쳐야 하고, 하나라도 빼먹으면 그 메서드만 다르게 동작해
- 결제 코드(**핵심 기능**)와 시간 재는 코드(**부가 기능**)가 섞여서 진짜 결제 로직이 잘 안 보여

## 함수로 묶어도 남는 것

```java
public void pay(Long orderId) {
    long start = timer.start();
    // 결제 처리
    timer.end("pay", start);
}
```

중복은 줄었지만 `timer`를 **부르는 코드**는 여전히 메서드마다 n군데 남아. 결제 코드를 아예 안 건드리는 방법이 필요해.

## 프록시

연예인한테 바로 연락하지 못하고 **매니저**를 거치는 것처럼, 진짜 객체 앞에서 요청을 대신 받는 대리인을 **프록시**라고 해.

팬(호출하는 쪽) → 매니저(프록시) → 연예인(`PaymentService`)

매니저가 하는 일:

1. 시작 시간 기록
2. 진짜 `pay()` 실행
3. 끝 시간 기록하고 로그 남기기
4. 결과를 그대로 돌려주기

**중요한 점**: 시간 재는 매니저는 결과를 걸러내거나 바꾸면 안 돼. 에러가 나도 시간은 남기고, 에러는 그대로 던져.

## AOP

여러 메서드에 공통으로 필요한 부가 기능(시간 재기, 로그, 트랜잭션)을 한 곳에 모아두고, 프록시가 메서드 앞뒤에 자동으로 끼워 넣게 하는 방법이 **AOP**(관점 지향 프로그래밍)야.

```groovy
// build.gradle (Spring Boot 3 기준)
implementation 'org.springframework.boot:spring-boot-starter-aop'
```

```java
@Slf4j
@Aspect      // 이 클래스가 매니저(공통 기능 모음)라는 표시
@Component
public class TimeLogAspect {

    // PaymentService의 모든 메서드 앞뒤에 끼어들기
    @Around("execution(* com.example.payment.PaymentService.*(..))")
    public Object logTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        try {
            return joinPoint.proceed();   // 진짜 메서드 실행 (연예인한테 넘기기)
        } finally {                       // 에러가 나도 시간은 남김
            long end = System.currentTimeMillis();
            log.info("{} 실행 시간: {}ms", joinPoint.getSignature().getName(), end - start);
        }
    }
}
```

```java
@Service
public class PaymentService {

    public void pay(Long orderId) {
        // 결제 처리만
    }

    public void refund(Long orderId) {
        // 환불 처리만
    }
}
```

이제 메서드가 30개가 돼도, 시간 재는 방식이 바뀌어도 `TimeLogAspect` 하나만 고치면 돼.

## 실무에서는

`@Transactional`도 같은 원리야. 프록시가 트랜잭션 시작 → 진짜 메서드 실행 → 커밋 또는 롤백을 대신 해줘. 그래서 서비스 코드에 트랜잭션을 시작하고 커밋하는 코드가 없어도 되는 거야.

## 내가 놓쳤던 점

- 함수로 묶으면 끝이라고 생각함. 함수로 묶어도 부르는 코드는 n군데 남음
- 매니저가 오류나 값을 "걸러낸다"고 함. 시간 재는 프록시는 결과를 바꾸지 않고 그대로 넘겨야 함
- 프록시, AOP라는 이름을 몰랐음
