# DI와 생성자 주입, 밑바닥부터

> 📅 2026-11-23 · 백엔드 기초 · 80점
> `#Spring` `#DI` `#생성자주입` `#빈`
> new로 직접 만드는 코드에서 출발해 DI, 스프링 빈, 생성자 주입이 왜 필요한지 단계별로 정리

## 의존

주문(`OrderService`)을 처리하려면 결제(`PaymentService`)가 필요해.
이렇게 **A가 B 없이는 일을 못 하는 관계**를 **의존**이라고 해.

## 직접 만들면 생기는 문제

```java
public class OrderService {

    private PaymentService paymentService = new PaymentService(); // 내가 직접 만듦
}
```

- 결제를 카카오페이에서 토스로 바꾸려면 `OrderService` 코드를 열어서 고쳐야 해
- 테스트할 때도 진짜 결제 객체가 만들어져

요리사가 재료까지 직접 농장 가서 키우는 셈이야.

## 밖에서 넣어주기 (DI)

직접 `new` 하지 말고 **밖에서 넣어주자**는 게 **의존성 주입(DI, Dependency Injection)**이야.
요리사는 요리만 하고, 재료는 납품업체가 가져다줘.

## 스프링이 납품업체

- `@Service`, `@Repository` 같은 걸 붙이면 스프링이 앱 켤 때 그 객체를 **미리 만들어서 보관**해. 이 객체를 **빈(Bean)**이라고 불러
- 그리고 필요한 곳에 **알아서 넣어줘**

그래서 스프링 코드에는 `new PaymentService()`가 안 보여.

## 넣어주는 통로 2가지

| 방식 | 비유 |
|---|---|
| 필드 주입 | 요리사가 일을 시작한 **다음에** 재료를 몰래 꽂아줌 |
| 생성자 주입 | 요리사가 **출근할 때** 재료를 들고 들어옴. 없으면 출근 자체가 안 됨 |

필드 주입:

```java
@Service
public class OrderService {

    @Autowired
    private PaymentService paymentService;

    @Autowired
    private OrderRepository orderRepository;
}
```

생성자 주입:

```java
@Service
public class OrderService {

    private final PaymentService paymentService;
    private final OrderRepository orderRepository;

    // 생성자가 하나면 @Autowired 생략 가능
    public OrderService(PaymentService paymentService, OrderRepository orderRepository) {
        this.paymentService = paymentService;
        this.orderRepository = orderRepository;
    }
}
```

롬복을 쓰면 생성자를 `@RequiredArgsConstructor` 한 줄로 대신할 수 있어 (`final` 필드를 받는 생성자를 만들어줌).

## 생성자 주입이 나은 이유

1. **불변**: `final`을 붙일 수 있어서 한 번 들어오면 아무도 못 바꿔. 필드 주입은 객체를 만든 *다음에* 값을 꽂는 방식이라 `final`을 못 붙여
2. **누락을 바로 발견**: 재료가 없으면 객체가 아예 안 만들어져서 **앱 켤 때** 에러가 나. 필드 주입은 `null`인 채로 만들어져서 **주문이 들어온 순간** NPE로 터져
3. **테스트가 쉬움**: `new OrderService(가짜결제, 가짜저장소)`처럼 스프링 없이 바로 만들어서 테스트할 수 있어

**중요한 점**: 흐름은 **의존 → 직접 만들면 불편 → 밖에서 넣어주기(DI) → 스프링이 대신 → 생성자로 받는 게 제일 안전** 순서야.

## 내가 놓쳤던 점

- 생성자 주입도 **스프링이 넣어주는 것**. 차이는 "어디로" 넣느냐
- `final`은 필드 주입에는 못 붙임. 생성자 주입이라서 가능한 장점
- 세 번째 이유인 **테스트가 쉽다**를 빠뜨림
