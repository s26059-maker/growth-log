# Map으로 결제 수단 고르기 (전략 패턴)

> 📅 2026-11-26 · 백엔드 기초 · 80점
> `#Spring` `#전략패턴` `#Map주입` `#빈`
> if-else로 결제 수단을 고르던 코드를 Map<String, PaymentService> 주입으로 바꿔, 새 결제 수단은 클래스만 추가하면 되게 만든 전략 패턴 정리

## if문으로 고르면 생기는 문제

사용자가 결제 수단을 직접 고르는 기능을 if문으로 짜면 이렇게 돼.

```java
@Service
public class OrderService {

    private final KakaoPayService kakaoPayService;
    private final TossPayService tossPayService;

    public OrderService(KakaoPayService kakaoPayService, TossPayService tossPayService) {
        this.kakaoPayService = kakaoPayService;
        this.tossPayService = tossPayService;
    }

    public void order(String payType, int price) {
        if (payType.equals("kakao")) {
            kakaoPayService.pay(price);
        } else if (payType.equals("toss")) {
            tossPayService.pay(price);
        }
    }
}
```

- 네이버페이가 추가되면 필드, 생성자, `else if`까지 **3군데**를 고쳐야 해
- 결제 수단이 늘수록 `else if`가 계속 쌓여
- `OrderService`가 카카오, 토스 같은 **구현을 다 알고** 있어

## 빈 이름 직접 정하기

`@Service` 괄호 안에 이름을 적으면 그게 빈 이름이 돼.

```java
@Service("kakao")
public class KakaoPayService implements PaymentService { ... }

@Service("toss")
public class TossPayService implements PaymentService { ... }
```

## Map으로 전부 받기

생성자에 `Map<String, PaymentService>`를 적으면, 스프링이 `PaymentService` 빈을 **전부** 찾아서 이름표(빈 이름)를 붙여 넣어줘.

| 키 (빈 이름) | 값 (빈) |
|---|---|
| `"kakao"` | KakaoPayService |
| `"toss"` | TossPayService |

**"이름 → 결제 직원" 명단**이라고 생각하면 돼.

```java
@Service
public class OrderService {

    private final Map<String, PaymentService> paymentServices;

    public OrderService(Map<String, PaymentService> paymentServices) {
        this.paymentServices = paymentServices;
    }

    public void order(String payType, int price) {
        PaymentService paymentService = paymentServices.get(payType); // 명단에서 이름으로 찾기
        if (paymentService == null) {                                   // 명단에 없는 결제 수단
            throw new IllegalArgumentException("지원하지 않는 결제 수단: " + payType);
        }
        paymentService.pay(price);
    }
}
```

명단에 없는 이름을 찾으면 `get()`이 `null`을 돌려줘. 그대로 `.pay()`를 부르면 NPE가 나니까, **알아보기 쉬운 에러**로 먼저 막아.

## 새 결제 수단 추가

```java
@Service("naver")
public class NaverPayService implements PaymentService { ... }
```

**클래스 하나만 추가하면 끝.** `OrderService`는 한 글자도 안 고쳐.

| | if문 버전 | Map 버전 |
|---|---|---|
| 네이버페이 추가 | 3군데 수정 | 클래스 하나 추가 |
| OrderService가 아는 것 | 카카오, 토스 **구현** | `PaymentService` **역할**만 |

**중요한 점**: 상황에 따라 갈아끼우는 "전략"들을 모아두고 골라 쓰는 걸 **전략 패턴**이라고 해. "역할만 알고 구현은 모른다"를 끝까지 지킨 결과야.

## 내가 놓쳤던 점

- 처음엔 Map으로 받는 **코드**를 못 써서 밑바닥부터 다시 배움
- 빈 이름을 직접 정하는 법(`@Service("kakao")`)이 기억 안 났음
- if문의 진짜 문제는 길어지는 것보다, `OrderService`가 **구현을 다 알게 되는 것**
