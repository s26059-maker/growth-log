# 인터페이스로 결제 바꾸기와 @Primary

> 📅 2026-11-24 · 백엔드 기초 · 85점
> `#Spring` `#인터페이스` `#Primary` `#빈`
> 결제를 인터페이스로 나눠 구현체를 갈아끼우고, 같은 타입 빈이 2개일 때 @Primary로 기본값을 정하는 법을 정리

## 역할과 구현

어제 코드는 `OrderService` 안에 카카오페이가 직접 박혀 있었어. 토스로 바꾸려면 `OrderService`를 고쳐야 했지.

```java
// 어제: 구현(카카오페이)이 직접 박혀 있음
private PaymentService paymentService = new KakaoPayService();

// 오늘: 역할(PaymentService)만 앎
private final PaymentService paymentService;
```

- **인터페이스** = 역할 (결제 담당)
- **구현체** = 그 역할을 실제로 하는 사람 (카카오페이, 토스)

`OrderService`는 **역할만 알고 누가 하는지는 몰라.** 그래서 카카오에서 토스로 바꿔도 `OrderService`는 안 고쳐.
콘센트 규격(인터페이스)만 맞으면 어떤 전자제품(구현체)이든 꽂히는 것과 같아.

```java
public interface PaymentService {
    void pay(int price);
}

@Service
public class KakaoPayService implements PaymentService {
    public void pay(int price) { /* 카카오페이 결제 */ }
}

@Service
public class TossPayService implements PaymentService {
    public void pay(int price) { /* 토스 결제 */ }
}
```

## 헷갈리는 용어

| 용어 | 뜻 | 예시 |
|---|---|---|
| 오버로딩 | 이름은 같고 **매개변수만 다른** 메서드를 여러 개 만들기 | `pay(int)`, `pay(int, String)` |
| 오버라이딩 | 부모가 정한 메서드를 자식이 **자기 방식으로 다시 구현** | 카카오, 토스가 각자 `pay()` 구현 |
| `extends` | 클래스 **상속** | `class A extends B` |
| `implements` | 인터페이스 **구현** | `class KakaoPayService implements PaymentService` |

## 빈이 2개면

1. 스프링은 `OrderService` 생성자를 보고 "`PaymentService` **타입**을 넣어줘야겠다" 하고 빈 보관함을 뒤져
2. 근데 `PaymentService` 타입 빈이 **카카오, 토스 2개**야
3. 스프링은 마음대로 하나를 고르지 않아. 에러를 내고 **앱이 안 켜져** (`NoUniqueBeanDefinitionException`)

납품업체에 "결제 담당 한 명 보내줘" 했는데 결제 담당이 2명이라 아무도 안 보낸 상황이야.

**중요한 점**: 문제가 **앱 켤 때 일찍** 터지는 거라 오히려 좋아. 주문이 들어왔을 때 터지는 것보다 훨씬 나아.

## @Primary로 기본값 정하기

기본으로 쓸 쪽에 `@Primary`를 붙이면, 여러 개일 때 그걸 넣어줘.

```java
@Primary
@Service
public class KakaoPayService implements PaymentService {
    public void pay(int price) { /* 카카오페이 결제 */ }
}
```

## 실무에서는

- `@Primary`: "대부분은 이거 써" 하는 **기본값**
- `@Qualifier`: **특정 자리에서만** 다른 걸 쓰고 싶을 때. 예를 들어 환불만 토스로 하는 경우

```java
@Service
public class RefundService {

    private final PaymentService paymentService;

    public RefundService(@Qualifier("tossPayService") PaymentService paymentService) {
        this.paymentService = paymentService; // 여기만 토스
    }
}
```

**중요한 점**: `@Qualifier`로 콕 집어 지정하면 `@Primary`보다 우선해.

## 내가 놓쳤던 점

- 오버로딩이 아니라 **오버라이딩**, 상속(`extends`)이 아니라 **구현**(`implements`)
- 처음엔 `OrderService`를 고쳐야 한다고 답했는데, 역할만 알기 때문에 **안 고쳐도 됨**
- 같은 타입 빈이 2개면 스프링이 못 고르고 **앱이 안 켜짐**
