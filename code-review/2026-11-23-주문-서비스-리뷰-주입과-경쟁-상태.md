# 주문 서비스 리뷰: 주입과 경쟁 상태

> 📅 2026-11-23 · 코드 리뷰 · 85점
> `#코드리뷰` `#생성자주입` `#경쟁상태` `#AtomicInteger`
> 필드 주입, new 직접 생성, 싱글톤 공유 필드를 찾아 생성자 주입과 AtomicInteger로 고친 리뷰

## 리뷰한 코드

주문을 받아서 결제하고, 저장하고, 오늘 주문 수를 세는 서비스.

```java
@Service
public class OrderService {

    @Autowired
    private OrderRepository orderRepository;                      // 문제 1

    private PaymentService paymentService = new PaymentService(); // 문제 2

    private int todayOrderCount = 0;                              // 문제 3

    public Long order(Long itemId, int price) {
        paymentService.pay(price);

        Order order = new Order(itemId, price);
        orderRepository.save(order);

        todayOrderCount++;                                        // 문제 3
        return order.getId();
    }
}
```

## 필드 주입

`@Autowired` 필드 주입은 `final`을 못 쓰고, 빠뜨려도 주문이 들어와서야 NPE로 터져.
→ **생성자 주입**으로 바꾸기 (`final` + 생성자)

**중요한 점**: `@Autowired`만 지우면 안 돼. 스프링이 아무것도 안 넣어줘서 `null`이 돼.

## new로 직접 생성

`PaymentService`를 직접 만들면 스프링 빈이 아니라서, 결제 방식을 바꾸거나 테스트할 때 가짜로 갈아끼울 수가 없어.
→ `PaymentService`도 빈(`@Service`)으로 만들고 **생성자로 주입받기**

## 싱글톤의 공유 필드

`OrderService`는 싱글톤이라 **딱 하나**를 모든 요청 스레드가 같이 써. 그래서 `todayOrderCount`는 모두가 같이 쓰는 거실(힙)에 있어.
`count++`는 **읽기 → +1 → 쓰기** 세 단계라, 두 요청이 동시에 0을 읽고 각자 1을 쓰면 주문 2개가 **1**로 남아.

| 용어 | 뜻 | 비유 |
|---|---|---|
| 임계 구역 | 동시에 들어가면 안 되는 코드 구역 (`count++` 줄) | 화장실 |
| 경쟁 상태 | 동시에 들어가서 값이 꼬이는 사고 | 두 명이 동시에 들어감 |
| 락 | 한 번에 하나만 들어가게 막기 | 문 잠그기 |

고치는 법:
- `AtomicInteger`: 읽기 + 1 + 쓰기를 한 번에 처리해서 끼어들 틈이 없음 (제일 간단)
- `synchronized`: 쓸 거면 잠그는 범위를 최소로. 메서드 전체에 걸면 결제까지 전부 줄 서서 느려져
- 실무: 서버가 여러 대면 메모리에서 센 개수가 서버마다 달라져서, DB에서 세거나 Redis `INCR`을 써

## 고친 코드

```java
@Service
public class OrderService {

    private final OrderRepository orderRepository;
    private final PaymentService paymentService;
    private final AtomicInteger todayOrderCount = new AtomicInteger();

    public OrderService(OrderRepository orderRepository, PaymentService paymentService) {
        this.orderRepository = orderRepository;
        this.paymentService = paymentService;
    }

    public Long order(Long itemId, int price) {
        paymentService.pay(price);

        Order order = new Order(itemId, price);
        orderRepository.save(order);

        todayOrderCount.incrementAndGet();
        return order.getId();
    }
}
```

## 내가 놓쳤던 점

- `@Autowired`만 지우는 건 해결이 아님. 생성자 주입으로 바꿔야 함
- 주문 번호(Long)와 주문 개수(int)는 다른 값이라 타입이 달라도 문제없음
- 임계 구역(구역)과 경쟁 상태(사고)를 구분하기. 락 범위는 최소로
